# Skill 沉淀与维护规范

## 1. 什么值得沉淀

Skill 应来自可重复的真实工作：有明确触发场景、输入、输出、判断标准和验收方法。沉淀会改变 Agent 决策的知识，例如源材料优先级、质量标准、版本差异处理、常见失败和可靠操作顺序。

不把单次回答、泛泛建议或大量官方文档直接打包。创建前检查现有技能；同一目标的改进优先更新现有技能，独立目标才新增。用户要求沉淀时可先发布初版，但准确记录验证范围。

## 2. 目录与命名

```text
skills/<name>/
  SKILL.md
  agents/openai.yaml       # 可选：Agent 界面元数据
  references/             # 按需：详细标准、模式和参考
  scripts/                # 按需：可执行辅助工具
  assets/                 # 按需：输出中实际使用的模板或素材
```

名称使用小写字母、数字、单连字符，不超过 64 字符。不要创建空目录或占位模板；参考文件必须在入口或相应参考中被链接并说明读取条件。

`SKILL.md` 必须以 YAML frontmatter 开始，含 `name` 和 `description`。`description` 说明做什么、何时使用，必要时补充容易混淆的边界；不要写成无限扩大适用面的关键词集合。

若添加 `agents/openai.yaml`，字符串加引号，`default_prompt` 引用 `$<name>`，元数据与入口一致。默认保持正常自动发现；只有用户要求时才设为仅显式调用。

## 3. 入口内容

入口应明确以下事项，可以按工作性质灵活组织：

- 目标与适用范围，以及必要输入和交付物。
- 必须读取哪些资料，哪些资料只在特定模式下读取。
- 如何选择来源、处理版本或来源缺失、决定下一步。
- 能实际执行的制作流程、停止条件与恢复方式。
- 关键约束及验收方法。

给 Agent 留出合理实施空间。固定步骤只用于有可靠性理由的环节；不能靠机械字数、页数、测试数量或文件数来假定质量。

模板变量写成清楚的占位参数，例如 `<输出目录>`，不要混入原任务中的账号、绝对路径、秘密或私有数据。示例要标明示例，不能让 Agent 误把它当作执行目标。

## 4. 资料、权限与运行环境

技能不得编造来源、日志、时间戳和执行结果。涉及公开来源时使用可核验的链接；易变 API 要查当前官方资料，并保留任务实际使用的版本。

技能遵循用户任务的授权边界，不凭“按技能执行”默认获得账号创建、外部消息、发布、删除和费用支出权限。工具失败或权限不足要说明具体阻碍和可完成部分，不绕过限制。

优先使用当前环境工具，不固化原机器解释器、字体或浏览器路径。必要依赖写清楚；只读诊断与实际写入操作要能区分。跨格式制作时可调用目标环境存在的专业技能，并提供不存在时的合理降级方式。

## 5. 脚本与资源

重复操作或精确转换有明显收益时再添加脚本。脚本具备参数、清晰错误输出和失败退出码；避免静默覆盖已有成果。针对破坏性操作必须核验目标和授权。

选择最少必要依赖。实际验证正常输入、关键失败路径和资源边界；需要外部权限或付费的测试只在授权范围内执行。结构检查必须明确自己不能证明的事项。

参考资料保持单一权威位置。模板应能被实际使用；不提交缓存、解释器环境、无关成品、大文件或未授权素材。

## 6. 版本与索引

在根目录 `catalog.json` 登记：`name`、`path`、`summary`、`version`、`status` 和 `verification`。路径指向 skill 目录；版本使用 `major.minor.patch`。

- `patch`：纠错、澄清或不改变使用契约的小修。
- `minor`：兼容的新模式、资源或能力。
- `major`：改变必需输入、输出契约或操作边界，需要迁移说明。

状态使用 `draft`、`active`、`deprecated`。初版 `active` 表示可按声明范围使用，并不表示经过全面运行验证。验证记录列出日期、实际方法、结果和未验证事项，不用笼统“全部测试通过”。

新增、重命名或弃用同步 README 索引。修改已有 skill 保留无关元数据；破坏性变更说明受影响使用方式和迁移步骤。

## 7. 完成标准

提交前逐项确认：

1. 触发范围明确，与已有技能的边界合理。
2. 入口能够独立指导任务，必要引用存在，跨机器参数清楚。
3. 来源、权限和失败处理准确，未把未执行内容声明为成功。
4. 辅助脚本行为已验证，实际任务样例达到预期输出标准。
5. `python scripts/validate_skills.py` 通过，索引和版本同步。
6. 验证记录明确未完成的真实任务测试和环境限制。

复杂流程推荐在隔离目录做一次代表性任务试作；没有授权或可用素材时，提交结构合格初版并标明行为验证缺口。

## 8. 给其它 Agent 的任务示例

```text
把本次已完成任务中的可复用方法沉淀到 guigui_skill_factory。
先读 AGENTS.md 与 docs/SKILL_STANDARD.md，检查已有 skill 是否可扩展。
明确触发场景、输入输出、来源、关键判断、失败处理和验收方法。
按需添加 references/scripts/assets，更新 catalog.json 与 README。
运行结构检查，并记录实际行为验证与未验证事项。
交付可审查的本地修改；远端提交按本任务已有授权执行。
```
