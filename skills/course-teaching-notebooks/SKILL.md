# 课程教学 Notebook

把讲义知识点转成可观察、可修改、可验证的学习过程。依据用户认可的教学样板沉淀，目标是让学习者理解代码为何产生这些结果，并能独立应用。

开始制作前完整读取 [教学设计与验收标准](references/teaching-standard.md)。本 skill 可直接使用已有讲义；如果还需采集课程资料或制作七件套，可在目标环境提供 `course-lecture-notes` 时配合使用，不依赖它才能工作。

## 工作流程

1. 阅读讲义、实验和可用官方代码，确定教学目标、真实来源与章节顺序。明确本次输出范围，保留现有 Notebook 中的用户修改。
2. 建立知识点 → 教学实验 → 可观察输出 → 验证方法的映射。概念课可合并主题，复杂实操可拆分，不机械规定一课一文件。
3. 选择运行模式。优先制作独立可运行的最小演示；需要真实模型或平台验证的内容另设环境与执行步骤，遵循已授予的权限和费用范围。
4. 以短 Markdown 与聚焦代码单元交替组织“预测 → 运行 → 观察 → 修改 → 验证”。保留重要解释、例子、局限及讲义和官方代码入口。
5. 加入参数实验、预期错误与独立练习。练习起始版本可运行，展示未通过项；参考解独立命名并真实验证，不能让学生空缺阻断运行全部。
6. 用 Notebook 安全工具生成/编辑 ipynb，验证结构，然后从新内核顺序执行。输出结论必须由实际结果支持。
7. 保存执行输出、导出 HTML、检查显示；运行本 skill 的只读检查脚本，记录内容核对、运行和视觉验证的范围与缺口。
8. 交付 Notebook、HTML 阅读版和运行说明；批量时维护每课来源、模式、覆盖与验证状态。未经用户确认样板风格，不自动扩大到整批课程。

## 关键要求

- 原课内容、官方代码、自编适配和生产扩展清楚区分；来源与版本差异可追溯。
- 模拟数据/固定响应不能当成真实平台结果。Python 权限 wrapper 不等于数据库权限；本地 SQL 不证明云端 GRANT 或身份配置。
- 每个核心教学问题有具体输出可观察：字段/行对比、图、召回片段、工具参数与返回、异常或检查结果。避免只打印“执行成功”。
- 参数实验说明可修改内容、预期变化和需要重跑的单元格。从头运行不依赖隐藏状态；重置和恢复行为清楚。
- 保存真实输出，避免全局显示限制把关键表或检查项折叠。大数据只展示代表性内容，说明样本范围。
- 运行、内容核对与视觉检查分别报告。浏览器或渲染工具不可用时记录视觉未验证，不绕过访问限制、不声称检查完成。

## 交付与复用

建议输出到课程的 `notebooks/`：`Lxx-主题-教学.ipynb`、同名 `.html`、运行说明和验证记录。保留讲义相对链接；不能运行的真实平台代码可放 Markdown 代码块或独立文件，避免混入默认运行路径。

依赖优先采用当前环境可用的 `nbformat`、`nbclient` 和 `nbconvert`；需要展示数据再添加 pandas 等。避免硬编码原机器路径、账户、内核版本和密钥。若当前环境提供专业 Notebook 技能，可遵循其格式与渲染流程，同时保持这里的教学标准。

执行完后检查（此脚本不执行代码，也不证明输出新鲜或视觉合格）：

```text
python <skill目录>/scripts/check_notebook.py <Notebook路径> --require-executed
```

用户提出批量需求时按课节独立输出、持久化验证进度；多 Agent 分工必须已有授权，且避免同时修改同一 Notebook 或课程索引。
