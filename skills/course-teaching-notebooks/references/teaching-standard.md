# 教学设计与验收标准

## 设计依据

经用户认可的 L05 样板包含 33 个单元格、14 个代码单元和 19 项断言；这只是实践记录，不能作为后续课程的数量指标。
样板用合成 HR 数据和内存 SQLite 展示标签、视图、假名 ID、多身份权限模拟、撤权、掩码、小样本聚合泄露、固定工具、审计和练习。
已运行本地代码并检查保存结果，用户确认了阅读质量；真实 Databricks 操作未执行，制作 Agent 的浏览器视觉检查受本地文件策略限制。
仓库不附带课程视频、生成讲义或原始私有材料。本标准足以复用教学方式，不依赖原机器的样板路径。

## 讲义到 Notebook 的转换

先阅读讲义与实验，提取核心目标、先修知识、原理、步骤、限制和失败案例。按下列关系形成覆盖表：

| 讲义内容 | 教学活动 | 输出 | 检查 |
|---|---|---|---|
| 核心概念 | 最小示例与解释 | 可读结果及其含义 | 能检验概念的断言或对比 |
| 算法参数 | 修改一个条件 | 前后结果 | 边界、趋势或预期差异 |
| 系统流程 | 分步执行并展示中间态 | 输入、过程、输出 | 阶段间契约与完整性 |
| 易错点 | 故意触发可控失败 | 错误类型与原因 | 修复前后对比 |
| 平台能力 | 真实环境操作或明确模拟 | 平台输出或模拟证据 | 两者验证范围分开 |
| 项目应用 | 组合实验和独立练习 | 应用结果 | 答案、完成标准与局限 |

技术结论应可追溯到讲义章节、官方文件/版本或字幕/PPT 锚点。缺失来源不伪造；没有正式匿名性、权限或质量证明时不使用强结论。
详细背景可链接讲义，但完成本 Notebook 的必要原理、前提、操作和结果解释必须在正文中。

## 单个教学单元

1. 提出具体问题，交代为什么要做以及输入。
2. 邀请预测结果，说明运行后观察什么。
3. 一段聚焦代码；复杂步骤拆分，代码必须是讲解对象而非封装后看不到的黑盒。
4. 可见输出，紧邻解释：发生了什么、为什么、能得出什么结论。
5. 修改一个参数/输入/条件，比较结果并说明依赖。
6. 验证关键性质，附独立应用题或连接下一单元。

可以按主题适度合并，不要求每段都机械重复六个标题。需要函数抽象时先展示其关键逻辑，后续再复用。

## 总体结构

默认顺序：学习目标与导航 → 环境与运行模式 → 最小可运行示例 → 分知识点教学单元 → 组合实验 → 独立练习 → 参考答案 → 复习与真实项目迁移。

环境单元说明 Python/内核、依赖、数据来源、参数和状态重置。运行环境支持时实际执行；不得让运行全部静默安装包、下载大型模型、创建账号、赋予权限或启动付费计算。

本地模式可用合成数据、SQLite、固定响应等，但标明替代的能力和不能验证的部分。
真实模式接入官方实验/服务，单独说明凭据来源、版本、操作、成本、持久化写入与验证状态。凭据不写进 Notebook 或输出。
不能执行的平台步骤用 Markdown 示例或单独文件，不以裸代码单元破坏默认的可运行路径。

## 输出如何服务教学

| 主题 | 主要观察对象 |
|---|---|
| 数据治理 | 字段/人数变化、连接基数、身份允许/拒绝、默认掩码、聚合泄露 |
| OCR | 原页面局部、识别文本、结构字段、错字/版面差异 |
| RAG | chunk、召回片段与得分、上下文、回答与引用、检索失败 |
| Agent | 工具名、参数、返回、状态转移、失败处理和审计 |
| 缓存 | 相似度/阈值、命中与未命中、复用内容、真实测量耗时 |
| 评估 | 逐例结果、失败样例、评判依据和统计范围 |

有助理解时使用图，不能为了图而制造数据。实际耗时与成本由运行测量，不编造“提升百分比”。
交互控件只在明显改善探索且环境支持时添加；关键输出仍保留可离线阅读的静态表/图。
表格不能截掉关键判断，检查汇总尽量完整显示。解释和数据保持相邻，控制过长日志。

## 练习、失败与答案

练习起始代码必须可运行，可故意只完成部分逻辑并在评分表显示不合格项。避免 `TODO` 空函数或未处理异常阻断默认顺序运行。
参考解放在练习之后，使用独立名称；不偷偷覆盖学生答案并宣布学生通过。
预期异常用明确类型捕获，解释失败原因；不要用无范围的 `except` 吞掉非预期错误。
真实错误不得伪造为成功输出，模拟日志要标明性质。
修改例子明确需重跑范围；污染权限或数据库时可恢复，必要时使用 `try/finally`。

## 可重复运行与编辑

使用 nbformat 或环境支持的 Notebook 工具生成、验证文件。已存在用户修改时做针对性编辑，避免整份重建覆盖练习。
依赖和数据路径可迁移，合成数据/随机过程确定性可复现。真实数据的版本、快照和变动说明清楚。
构建脚本若会覆盖同名输出，应明确提示或支持另存；不得无提示替换用户编辑成果。
可在授权范围内使用 nbclient 从新内核运行，并通过 nbconvert 导出 HTML。
Notebook 里执行计数齐全仅证明保存了执行状态；真正的新内核运行记录才能支持可复现性声明。

## 验收与交付

- 覆盖：核心知识点有实验/解释与来源对应，实际平台缺口清楚。
- 格式：nbformat 验证通过，内核和相对链接正确。
- 运行：新内核顺序执行，无非预期错误；保存输出，记录版本和已执行范围。
- 结果：断言真实检验行为，重点表/图与解释一致，练习错误与参考解区分。
- 阅读：打开保存 Notebook 或 HTML 检查标题、中文字体、代码和表/图；记录实际检查方式。
- 状态：内容核对、执行、输出核对、视觉检查、真实平台执行分别记录，不用笼统“全部通过”。

工具不可用时提供可阅读成果与具体缺口。尊重浏览器安全限制，不为视觉检查绕过受限协议或访问控制。
交付 ipynb、HTML、简短运行说明和验证记录；课堂文件留在用户项目中，技能仓库只保存可复用规范与工具。

## 批量任务提示词

```text
使用 $course-teaching-notebooks，根据 <课程讲义目录> 制作 <指定课节> 的教学 Notebook。
输出到 <课程输出目录>/notebooks，保留讲义与官方代码的来源映射。
每个核心单元包含预测、运行、观察、修改和验证；显示中间结果，附练习与参考答案。
本地演示与真实平台明确区分；执行授权范围内代码，保存输出并导出 HTML。
逐课记录内容、运行、输出、视觉与真实平台验证状态；不要扩展到未授权课节。
```
