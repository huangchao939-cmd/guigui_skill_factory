# 课程讲义制作

将用户指定课程转为可独立学习、随手检索和项目应用的中文讲义。默认沿用本 skill 的七件套标准；用户已有目录、模板、课程顺序或交付格式时优先遵循。

## 读取与执行

开始制作前完整读取 [内容标准](references/content-standard.md)。批量课程、多 Agent 分工或中断续作时，再完整读取 [批量流程](references/batch-workflow.md)。

1. 检查输出目录及现有成果，确定课程顺序和真实章节清单。先建立来源清单，再制作正文。
2. 取得并核验用户提供或有权访问的字幕、视频、PPT、官方代码和资源页。按内容标准记录来源、时间戳和代码版本。
3. 每节完成七件套，随后整合课程级资料。详细讲义是主要成果，必须覆盖课程实际内容；文件数、页数和字数不能代替内容完整度。
4. 每节将字幕知识点和代码单元映射到讲义章节，逐项检查遗漏。解释错误、译文误解、代码与视频版本差异时回到原始资料核验。
5. 批量时更新持久化进度；先完成已具备资料的课节。必须登录或缺少必要来源时明确报告具体缺口，不把猜测写成逐字稿。
6. 运行本 skill 的结构检查，并按内容标准做语义和交付格式验收。只在实际通过的范围内声明完成。

## 必须保持的约束

- 来源可追溯：课程原讲、官方代码、补充解释、生产实践、外部扩展明确标记。
- 不编造时间戳、PPT 页码、字幕、官方代码或实验运行结果。用户粘贴的 Transcript 可以作为来源，但记录取得方式。
- 优先使用可靠官方字幕。中文音轨或自动转写明显不准确时，可以核查同课程官方英文字幕/视频，再翻译成中文；先确认章节对应，记录切换和纠错。
- 课堂实现与当前 API 不一致时并列说明；可提供标明版本的适配方案，保留原课逻辑。
- 代码需讲清输入、输出、执行流程、关键语义、依赖与限制。没有真实跑过的代码写明“未运行”，不声称验证成功。
- 资源缺失可提交已完成部分和缺口清单，但不能把来源状态说明算成已完成逐字稿。
- 默认只在用户指定范围内制作和组织成果。保留已有文件；不因批量制作自动删除视频、不自动发布网站、不自动创建账号或启动付费计算。

## 交付与格式

默认先交付 UTF-8 Markdown 知识库；PDF 是便于阅读的派生版本。若用户沿用先前包含 PDF 的标准，制作分课 PDF 和完整手册。PDF、Word、PPT 需遵循当前环境相应格式技能和渲染检查流程；未提供相应技能时使用可用工具并如实说明验证范围。避免把特定机器的字体、解释器或工具路径固化进跨机器流程。

批量任务可按用户授权分派；这个 skill 本身不要求启动子 Agent。每个执行 Agent 应完整读本 skill 及适用参考资料，并独占明确的课程或课节输出目录。

结构检查命令（将路径替换为实际位置）：

```text
python <skill目录>/scripts/validate_course.py <课程根目录>
```

该检查只验证目录、文件和进度清单，不验证教学正确性、来源真实性或实验是否执行。手工验收不可省略。
