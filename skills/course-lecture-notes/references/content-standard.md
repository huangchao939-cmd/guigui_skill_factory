# 讲义内容与验收标准

## 来源与覆盖

按真实课程顺序编号 L01、L02……；原课程若有模块保留模块层级。参考资料页、测验页和 Notebook 不能误算为视频课；非视频内容单独收录并链接到相关课节。

来源优先级：用户提供的官方材料、课程官方网站及官方仓库、产品官方文档、权威论文/标准；一般博客仅在必要时补充且标明性质。检索涉及当前产品功能/API 时核验官方资料。登录页面使用环境支持的浏览器工具，遵守会话与访问权限；失败时可使用用户提供的字幕和下载资料。

每个来源记录标题、URL 或本地路径、取得方式、语言、日期及适用章节。代码记录仓库和实际读取的文件路径、commit/tag；无法取得版本时明确说明。PPT 记录原始页号；没有 PPT 时不虚构课程幻灯片，可用文字或原创图解释。

原始字幕保持原样存档。中文精译可修复断句与明显语音识别错误，但要保留时间锚点，重要纠错记录依据。补充说明放入讲义，不能混入“精译”后冒充原讲。英文课程提供英文原文；中文课程如无官方英文字幕，不凭空制造官方英文稿，改为“官方原文逐字稿”，并记录语言。

建立覆盖表：时间段/幻灯片/代码单元 → 知识点 → 详细讲义章节 → 示例/实验。合并重复讲述、致谢与纯操作等待是允许的；原课的技术结论、关键演示、参数、限制、失败案例和操作前提必须覆盖。

## 每课七件套

命名默认 `lectures/L01-课节名/L01-资料名.md`。

| 文件 | 必须包含 |
|---|---|
| 官方英文逐字稿（或官方原文逐字稿） | 原文、时间戳、来源与语言；保留真实内容，无扩展观点 |
| 视频时间轴 | 时间区间、主题、关键结论、跳转对应讲义章节；时长取自真实来源 |
| 中文精译逐字稿 | 按时间顺序忠实翻译，术语一致，标记重要纠错 |
| 详细讲义 | 原课完整知识点、概念解释、例子、代码/PPT 导读、边界、误区、应用及来源 |
| 一页复习 | 学习目标、核心概念/关系、关键步骤、易错点、定位索引；导出时验证一页，不能靠极小字体强塞 |
| 闪卡与练习 | 原理问答、情景判断、代码/案例题；附答案与推理，区分仅背诵和实际应用 |
| 实验 | 环境/版本/前提、步骤、代码入口、预期结果、验证方法、失败排查、完成标准；概念课可用设计或诊断练习 |

详细讲义不应只是字幕摘要或链接集合。对每个核心概念讲清：它解决什么问题、如何工作、何时使用、限制是什么，以及至少一个可理解的例子。涉及公式时解释符号和简单计算；涉及系统流程时给最小有效流程图或表格。

对实操课依执行顺序解释 Notebook 或代码：数据输入、转换、关键调用、输出、依赖和验证。保留官方入口；精选必要片段并解释，避免无注释粘贴大段代码。提供独立示例时标为自编或适配代码，说明与官方代码的关系。生产扩展要与该课知识直接相关，并说明选择理由及适用条件，不能用大量泛泛建议代替原课讲解。

练习量按课节知识密度决定，不设机械字数和页数。短导论可以简短，复杂实验必须充分展开。练习答案应能让自学者判断自己错在哪里。

## 课程级成果

默认包含：README 导航、课程总览、概念地图、中英术语表、综合自测、官方资源导读、贯穿式项目、完整复习手册、学习进度、实施与验收报告。视课程内容增加治理矩阵、算法对比、架构对比或生产检查清单，不强制所有课程使用 Agent 治理结构。

完整手册整合课程导航、核心讲义、速查和练习；明确实验/原始字幕在何处查阅。电子版应有清晰标题、可搜索文本、来源链接和导航，PDF 宜有目录与书签。Markdown 原稿与 PDF 内容需一致。

## 验收

1. 数量：章节与官方顺序一致，每节七件套完整，原始来源与来源清单齐全。
2. 覆盖：逐项核对覆盖表，所有关键原课内容都有对应讲义位置；遗漏必须补齐或说明具体缺口。
3. 准确：核对重要术语、参数、公式、权限/安全语义；识别演示结论的适用范围，不能把演示成功写成生产就绪。
4. 代码：官方链接与实际文件一致；片段未混用不兼容版本。只报告真实执行的结果，明确实验未运行项及环境约束。
5. 教学：核心概念有解释与例子，练习有参考答案，实验有可判定的完成条件。
6. 可查阅：相对链接可解析、命名稳定、标题层级清晰、术语一致、来源与时间索引可追溯。
7. 派生格式：逐页渲染 PDF/Word，检查字体、表格、代码溢出、分页、图像、空白页；可提取文字不代表版式合格。修复后重新检查受影响页面。

验收报告分别记录来源/内容/代码执行/文件结构/渲染状态。数量通过只能称“结构通过”；缺少内容核对或有资料缺口时，不声明全部完成。
