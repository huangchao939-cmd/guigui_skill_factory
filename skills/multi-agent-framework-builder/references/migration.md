# v1 → v2 显式迁移

v2 将原 framework.json 分为 workflow.json、run.json 与实际 journal，增加图、输入版本、dispatch_id 和独立重试计数，是破坏性变更。不要直接覆盖进行中的工作包。

1. 用 v1 检查器核对旧状态；停止并核对旧执行者/外部副作用。脚本拒绝 running/reviewing 或含句柄的任务，不提供绕过开关。历史句柄确认失效后人工记录核对，再从副本去除，不删除证据。
2. 对旧目录执行 migrate_v1.py，--output 指向不存在且在旧目录外的新目录。原目录、旧报告/证据保持不动。
3. 迁移只复制安全角色文件、旧定义备份与新 workflow；不复制缓存/任意文件/运行状态。旧 PASS 不继承，新任务未派发。角色重叠/额外角色无法推断时拒绝，人工明确映射。
4. 阅读 MIGRATION-REVIEW.md，按 v2 重写提示词，补实际输入版本、scope 根、预算、授权、外部操作、接口/门禁与运行适配；不能保留脚本的 local/unset 默认就启动。
5. 先画新架构/流程图，补完整工作包，核对 workflow_revision，生成依赖图。迁移脚本故意不伪造手工图，结构检查此时应报缺图，直到完成审核。
6. 运行结构与模拟验证，再建立新 run。真实平台能力另测，旧业务产物可重新核验后接入，不人工复制旧 passed 状态。

脚本不迁移运行中的业务、不撤销外部副作用、不证明角色提示词已适配。失败会报错，已创建的不完整新目录保留供审查，不自动删除。
