# 验证标准与工具边界

## 三层验证

1. 结构：角色/依赖/路径/版本/证据引用及生成依赖图一致。
2. 模拟行为：固定规则在成功、并行汇合、修复、重复/过期结果、失效、超时、取消、重启、审批与预算下符合协议。
3. 真实平台：实际句柄、取消确认、隔离、业务测试、外部副作用/审批身份和运行成本。

逐层单独报告，不能互相代替。保存 evidence 的存在不证明内容真实；执行报告和人工架构/流程图需另行审查。Mermaid 来源生成成功不等于图片渲染/视觉检查通过。

## 工具行为

- validate_framework.py：只读，检测 workflow.json 时验证 v2，否则兼容 framework.json 的 v1 检查。v2 检查角色/静态 DAG/作用域格式/策略、图版本、生成图、journal 快照一致，以及 passed 的当前报告、执行报告摘要与逐项证据文件。未验证业务代码/真实输入文件摘要/人工图语义/权限。
- render_workflow.py：从定义生成 dependencies.mmd，不渲染图片。现有内容不一致时需 --overwrite，先审核差异。
- orchestration.py：纯状态转换和单写入者 journal。只接受 local 派发；external 拒绝，要求真实操作/审批 adapter。approve 仅模拟版本关联，不制造用户授权。输入 envelope 通过不代表实际文件哈希已核对。
- simulate_framework.py：运行 self_test.py 测试，生成串行与并行求和样例、实际事件/证据和 validation.json。目标必须不存在，无网络、模型、真实 Agent 或外部操作。
- migrate_v1.py：显式迁移到新目录；旧源不变，旧 PASS 不继承。拒绝关联执行句柄/在途任务；不生成假架构图或 run。

## 必需演练

串行完成、并行 all_required、重复结果 no-op、旧派发拒绝、修复成功/耗尽、资源冲突、容量、超时保留资源/核对后接管、取消/晚到结果、上游失效与审批失效、活跃后继不释放、预算停止但接收结果、权限拒绝不重试、假通过拒绝、旧 review/错误完成、循环/越界路径、外部 dispatch 拒绝、总派发限制、快照损坏恢复、journal 尾行损坏/重复事件停止。
外部成功后本地未记录的场景仅用 mock adapter 展示稳定键查询/去重，不能声称真实供应商支持幂等或 reducer 已实现 Saga。

新平台试跑先选择一个低风险任务，测输入核验、启动/等待、审查、取消确认与接管；需要新权限/费用时暂停。真实平台未测，交付明确 not_run。熔断、退避/jitter、deadline、身份核验、多进程锁、进程后台持续运行未接入时逐项标明，而非“生产可用”。
